# 学院级公开条目粒度

## 决策

日常新增的每一条公开招生信息必须对应一个官方明确可投的具体单位。`name` 记录学校或独立办学机构，`institute` 必须为该单位的完整官方名称；学院、系、研究院、国际学院、联合培养单位和其他官方招生单位均按此规则处理。所有候选 `institute` 类型只有在自身是官方明确列出的最小适用招生单位、且未列出更下级可申请单位时才可使用；独立研究生院或独立研究院同样适用这一统一条件。

校级/研究生院的总通知可以作为发现入口和字段证据，但不能单独形成“全院系”“全校”或未指明单位的公开条目。扫描器必须继续展开公告中的学院目录、报名系统、附件和子页面，并为每个明确可投的单位分别生成条目。

## 已实现的 additions-only 门禁

`7593f2a` 已在日常批准器中加入学院级新增身份检查，`d88e3f8` 先补强了格式控制字符防护，`a2a3182` 将明确标签比较收敛为更稳健的检查副本 skeleton。该检查只遍历本轮 `additions`，并在任何 release decision 或公开写入前执行：

- `projectId` 必须为四个非空段 `招生周期|name|institute|项目/轮次`，其中 `name` 和 `institute` 段分别与公开对象字段逐字一致；
- `institute` 含 Unicode `Cf` 格式控制字符会被拒绝；用于明确标签拒绝的检查副本依次 NFKD、删除 Unicode `White_Space`、`Punctuation`、`Symbol` 与 `Mark`，再转小写；
- skeleton 含 `wholeschool`（包括 `whole-school` 的符号变体）、全校、全院系、各学院/各院系、校级（包括学校级）、招生系统/报名系统/系统级、研究生招生办公室或招生办公室时会被拒绝；
- skeleton 恰为研究生院，或恰为 `${skeleton(name)}研究生院` 时会被拒绝。含额外单位限定词的候选（例如 `新增测试大学深圳国际研究生院`）不会被此规则本身拒绝，仍须由官方字段证据和最小适用单位规则支撑。

检查副本只服务拒绝判断，不改写公开字段或字段证据；现有字段证据仍逐项与公开值精确比对。该门禁仅是明确标签/身份一致性的下限，不能从不透明官方来源推断未披露下级单位、确认学院名称等价性，或证明扫描器已完整 fan-out；扫描器仍需递归枚举官方明确列出的单位，未解通用通知继续留在私有队列。

## 失败语义

若官方页面只给出校级通知且不能从其正文、附件、系统或官方子页确认可投单位，则该线索保留在本轮私有重试队列，不公开泛校级条目；不得猜测、补全或复制学院名单。已实现的明确标签门禁会拒绝列出的学校范围/系统/办公室与未限定研究生院 `institute`，但不会把不透明来源自动拆分为学院清单。

同一官方通知明确覆盖多个单位时，每个单位独立成为一条新增项，并各自保留对应的 `institute`、稳定身份与可追溯官方证据。

## 兼容性

追加式发布不改写父快照。如有同招生周期、同学校的历史通用父项，它不替代学院级身份；有具体官方证据的单位级新增项可以追加，并与不可变的历史通用父项共存。日常工作不得隐藏、删除或降级父项；其移除、拆分、修正或合并只能在用户明确授权的独立维护迁移中完成。

公开 schema 未因本次变更而改变，但“仅为政策、尚未触及批准器”的表述已不适用：日常批准器已有上述 additions-only 机器门禁及聚焦回归案例。它不重新判定、改写或拒绝不可变历史父项，也不改变历史 `ScanBundle`/replay 输入；完整语义单位分类、扫描器 fan-out 完整性、全套测试与发布集成仍是独立范围，不能由这个门禁或本文档宣称完成。
